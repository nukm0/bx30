# Marketplace — полный список требований проекта

Этот документ фиксирует требования, которые должны войти в итоговую версию. Текущий архив содержит полный исходный проект Next.js и реализованную клиентскую часть; пункты, помеченные «НУЖЕН СЕРВЕР», нельзя безопасно завершить только в React/localStorage.

## Профили и права
- Единственный владелец платформы: Telegram ID `998579758` (@nukm0).
- Остальные аккаунты по умолчанию — обычные пользователи.
- Админ-панель и кабинет магазина отображаются только аккаунтам с назначенными правами.
- Верификация выдаётся вручную владельцем через форму: ФИО, телефон, Telegram ID, username, никнейм. ID — ключ записи; имя/username/фото должны обновляться из проверенного Telegram-профиля.
- В журнале хранить действие, цель, время и личность исполнителя: имя, username и Telegram ID.
- Роли: владелец, заместитель, администратор, модератор, стажёр, пользователь и владелец магазина. Заместитель не может изменить владельца или отменить решение владельца.

## Баннеры
- Создание с заголовком, описанием, фотографией, прямой ссылкой и датой создания.
- Рекомендуемый размер изображения: 1600 × 600 px (соотношение 8:3); интерфейс должен подсказывать размер.
- Две независимые галочки: главная страница и магазины; можно выбрать обе.
- Баннеры автоматически включаются в ротацию. Можно скрыть/вернуть, удалить окончательно.
- При клике открывать именно указанную ссылку, валидировать URL и не добавлять домен приложения к относительному URL.

## Магазины
- Создание магазина: название, описание, логотип, владелец.
- Один пользователь может владеть не более чем одним магазином.
- Магазин появляется в разделе «Магазины»; владелец получает значок 🏪 и пункт «ЛК магазин».
- В админ-подробностях показывать дату создания, статистику просмотров, подписчиков магазина, подписчиков объявлений, список объявлений с удалением и актуальные/закрытые жалобы.

## Жалобы и наказания
- В списке видны все жалобы; клик открывает полную карточку: отправитель, описание, материалы, объект жалобы и его владелец.
- Кнопка «Взять в работу» переводит жалобу в статус «В процессе» и показывает проверяющего.
- Проверяющий добавляет заключение и рекомендуемую меру. Меры: предупреждение, скрытие объявления, временный бан (дни/часы/минуты), постоянный бан, без наказания.
- Владелец видит первоначальную жалобу и материалы, заключение модератора и меру, затем может одобрить, изменить или пропустить наказание. Владелец может принять решение без заключения модератора; решение владельца имеет приоритет над действиями команды, кроме полномочий заместителя, определённых правилами.
- Жалоба о мошенничестве временно скрывает объявление до решения.
- Предупреждение приходит в уведомления. В уведомлении отображаются описание проверки, мера и заключение владельца.
- При блокировке экран показывает заголовок «Вы забанены», причину, оставшееся время или «Навсегда», кнопку апелляции в Telegram @nukm0 и предзаполненный текст с ID пользователя и причиной обращения.
- Бан привязывается к Telegram ID, а не username.

## FAQ
- Кнопка «Сотрудничество» закреплена сверху.
- «Как пользоваться» открывает инструкции по пользовательской навигации без описания административных полномочий.
- «Нарушения» открывает подробный разбор жалоб и безопасных сделок.
- Владелец может создавать/редактировать/удалять разделы, заголовки, пункты и подпункты с текстом ответа.
- Удалить нумерацию вида 01–014; контактный блок должен соответствовать тёмной графитовой теме с фиолетово-розовым градиентом.

## Обзор админ-панели
- Сводка созданных магазинов и баннеров с датой создания.
- Из обзора доступны действия скрыть, вернуть или удалить баннер, а также перейти к подробностям магазина.
- В разделе объявлений администрация может скрывать из рабочего списка уже проверенные нормальные объявления; это не должно удалять публикацию с пользовательской ленты.

## Требования безопасности — НУЖЕН СЕРВЕР
- Проверка подписи Telegram `initData` на сервере; `initDataUnsafe` использовать только для предварительного отображения.
- База данных для пользователей, верификации, ролей, магазинов, жалоб, банов, баннеров, FAQ и журнала аудита.
- Серверная проверка полномочий для каждого административного действия.
- Серверные сроки блокировки и серверная проверка бана при каждом запросе.
- Загрузка изображений в постоянное хранилище (не хранить большие base64 в localStorage).
- Реальная отправка уведомлений через Telegram-бота.

## Текущее состояние
Архив включает приложение Next.js и клиентские формы/экраны, описанные в README. Данные localStorage относятся только к текущему браузеру. Наличие поля или формы в интерфейсе не означает защищённого серверного исполнения. Перед публикацией необходимо выполнить `npm install`, `npm run build`, а после добавления серверной части — тесты доступа и интеграции.
