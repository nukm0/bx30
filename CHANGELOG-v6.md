# Marketplace — изменения v6 (переработка по ТЗ)

## Добавлено и исправлено

- Проверка Telegram Web App `initData` на сервере и получение роли из серверной таблицы. Telegram ID `998579758` закреплён за владельцем; клиентские настройки не выдают привилегии.
- API для назначений ролей, сессии Telegram, админского аудита, жалоб, банов, серверной загрузки фото, баннеров, магазинов, FAQ и подписок на магазины.
- Supabase-схема для пользователей, ролей, магазинов, баннеров, жалоб, банов, уведомлений, FAQ, модерации объявлений и журнала действий.
- Логотипы магазинов и фото-материалы жалоб загружаются через сервер; Service Role Key не отправляется в клиент.
- Назначение одного магазина на один Telegram ID; данные владельца берутся из серверной учётной записи.
- Ручная верификация владельцем с сохранением подтверждённых ФИО и телефона; верификационный бейдж показывается по данным сервера.
- Баннеры с раздельными размещениями, датами, скрытием/восстановлением/удалением и проверкой абсолютных `http(s)` URL.
- Жалобы с доказательствами и данными объекта, назначение ответственного модератора, заключение и окончательное решение владельца/заместителя, блокировки с причиной и сроком, уведомления и ссылка на апелляцию.
- Подписки на магазины хранятся на сервере; аудит показывает имя, username и Telegram ID сотрудника.
- Исправлены JSX-скобки в исходной странице админки; числовая сводка просмотров больше не содержит заранее заданного числа.

## Перед использованием

1. Создать проект Supabase и выполнить `supabase/schema.sql`.
2. Настроить переменные из `.env.example` на стороне сервера/Vercel.
3. Установить npm-зависимости и выполнить `npm run build`.
4. Проверить Mini App с реальной Telegram-сессией и тестовой базой, прежде чем публиковать изменения.

## Ограничения, которые остаются

- Полную установку зависимостей и production-сборку здесь проверить не удалось: npm registry не отвечает из рабочей среды. Проверка TypeScript не выявила ошибок разбора TS/JSX, но без типов Next.js/React это не заменяет сборку.
- Объявления, отзывы, избранное, пользовательские подписки и часть счётчиков/статистики ещё хранятся в клиентском состоянии; для полноценной синхронизации между устройствами их нужно перенести в Supabase и связать с API.
- Часть стартовых карточек товаров, магазинов и отзывов осталась как начальное UI-наполнение. Верификация, роли и ключевые административные действия защищены серверными обработчиками, но проект ещё требует интеграционных тестов и настройки инфраструктуры.

## Исправление сборки после проверки Vercel (15 октября 2026)
- Добавлено поле `subscriberCount?: number` в TypeScript-тип управляемых магазинов. Компонент «Подробнее о магазине» использует это поле с резервным подсчётом подписок, а загрузчик серверной конфигурации также сохраняет его в состояние. Это устраняет сообщённую ошибку `Property 'subscriberCount' does not exist on type ...`.
- Повторная полная сборка в текущем окружении не подтверждена: установка npm-зависимостей превысила лимит времени и `next` недоступен. После этого исправления нужно повторно запустить `npm run build` в Vercel.
